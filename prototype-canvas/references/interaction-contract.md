# 原型通信协议

画布外壳与唯一原型 iframe 使用 `postMessage`，消息必须带 `__prototypeCanvas: true` 和当前实例 Token。

导出的自包含 HTML 通过 `file://` 打开时，原型 iframe 必须使用 `srcdoc` 承载已注入桥接脚本的源码；不得把源码转为 `blob:null` 地址。后者在本地文件的 opaque origin（不透明源）环境中可能收到导航消息，却无法稳定完成桥接回放。只有已经返回 `prototype:render-stable` 且没有错误的节点内 iframe 才能提升为可交互预览；其他情况必须重新创建 iframe，并继续显示原快照直到回放成功。

桥接脚本必须插入源文档真实的 `</body>` 之前。定位结束标签时要跳过 `script`、`style` 等原始文本区域和 HTML 注释，不能替换源码中第一次出现的 `</body>` 字符串；自包含原型的框架或组件代码可能把完整 HTML 片段保存在 JavaScript 字符串中。

## 画布到原型

- `canvas:navigate`：传递当前用户类型专属 Binding（关联）及有序动作；没有专属 Binding 时才回退到 `global`。新节点、新用户类型或重新定位时使用从源 HTML 初始状态新建的 iframe，禁止复用其他业务状态。同一节点、同一用户类型且已完成回放的只读内嵌预览可直接提升为可交互预览，因为内嵌阶段不接收用户交互。
- iframe 的 `load` 只能作为桥接脚本未发出 `prototype:ready` 时的延迟兜底；一个加载周期内 `canvas:navigate` 只能发送一次，避免重复身份切换和重复页面动作。
- `canvas:start-locate` / `canvas:stop-locate`：开始或停止人工定位记录。

## 原型到画布

- `prototype:ready`：桥接加载完成。
- `prototype:render-stable`：动作播放完成，并已等待字体、图片和连续两帧渲染稳定；收到前必须保留快照。
- `prototype:render-error`：返回无法执行的入口或目标。
- `prototype:locate-update`：返回本次用户操作动作、目标选择器、可见弹层与活动 Tab 摘要。

人工定位时，收到 `prototype:ready` 后先发送 `canvas:start-locate`，再播放既有 Binding；程序触发的回放动作不计入记录。定位点击和变更必须在 `window` 捕获阶段监听，早于原型内部可能调用 `stopImmediatePropagation` 的处理器。回放过程同时返回已成功执行并重新解析过的动作前缀；用户确认时只把该前缀与本次新增操作合并，首个失败步骤及其后的旧路径必须舍弃。取消或候选路径验证失败时不修改 Manifest。

- 记录以“界面是否真的变化”为准：每次可信点击先记录，再比对点击前后的可见界面状态（可见弹层、可见页面容器、展开控件、活动 Tab、当前主区域文字）；没有引起变化的点击在保存前丢弃，避免把点空白、点表格等噪声写进关联。
- 禁止按选择器去重。同一按钮的连续点击可能推进业务状态（向导“下一步”、连续翻页、连续确认），只有“没有改变界面”的动作才允许丢弃。
- 目标页面按“这次操作让界面变成了什么”认定：优先本次新出现的弹层，其次是包含点击位置的最具体页面容器，并排除 `body` 与外壳容器（`data-shell-*`）；不得回退成整块工作区。
- 定位过程中把当前目标页面的简短名称显示给用户；确认前的候选路径与原关联完全一致时，必须提示“没有产生变化”，由用户选择重新定位或仍然保存。
- 关联保存成功后，若新快照与上一版完全相同，提示必须说明“预览图和上一版相同”，不得只提示“已更新”。

## 选择器

优先顺序：

1. 唯一 `id`。
2. 显式 `data-proto-scope`、`data-zann-*`、`data-page-*` 等语义属性。
3. 语义明确且唯一的 `data-*` 属性。
4. `aria-controls`、`aria-label` 与角色。
5. 稳定 class、同类型序号与有限层级组合。

不记录随机 class、屏幕坐标或依赖某条 Mock 数据文本的选择器作为唯一入口；缺少显式契约时允许有限的 `nth-of-type` 作为最后兜底。

每个动作与目标除主 `selector` 外，可保存 `selectors[]` 和 `locator`：

- `selectors[]` 保存从强到弱的备用语义选择器。
- `locator.tag`、`locator.role`、`locator.text` 和 `locator.attributes` 用于校验位置选择器是否仍指向原元素，并在 DOM 顺序变化后重新查找。
- 匹配位置选择器时如语义特征不一致，必须视为失效，不能点击当前序号对应的其他按钮。
- 每一步先等待元素出现且可见，再执行原型自身的点击或变更事件；下一步继续按实际 DOM 更新等待，不假定任意框架的渲染耗时。

## 通用导航兜底

- 优先点击 Manifest 已记录入口，让原型自己的脚本更新状态。
- 回放点击必须调用浏览器原生 `HTMLElement.prototype.click` 或等价事件，不能直接依赖目标元素的 `element.click` 属性；原型可能用同名字段覆盖该属性。
- 找不到入口但目标 DOM 已存在时，可在只读快照或预览中临时显隐目标；该兜底不能声称真实业务路径已验证。
- 完整原型模式打开失败时返回画布并显示失败步骤，不停留在空白页。
- AI 从 JavaScript 数据模型得到的路径只能作为候选，必须在当前用户类型下从原型初始状态完整重放成功后才可标记为有效关联。

## 用户类型与原型身份

- 用户类型画布只使用已验证的 Binding 动作切换原型已有身份；禁止注入原型不存在的权限逻辑。
- 实时 HTML 与快照采集必须使用同一套身份切换和动作回放内核，避免两种预览对同一 Binding 得出不同结果。
- 身份控件匹配应先一次性扫描已存在的语义属性和 `select` 选项；只有控件尚未生成时才做一次短时轮询，禁止按候选值逐个等待。localhost 允许复用 Chromium 进程，但每次快照必须新建隔离的 BrowserContext（浏览器上下文）。
- 单 HTML 的 URL 不作为导航状态依据。页面、Tab、弹窗和抽屉都通过动作序列与最终目标选择器恢复。
- 节点编辑定位先从初始 HTML 播放已有 Binding，再开始记录新增操作；确认后合并，取消时不写入。
